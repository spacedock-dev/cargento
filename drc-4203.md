## Problem

DRC-4203 remains a real shared-reducer prerequisite, but the issue describes an Antigravity wait as though it already reaches the board. It does not: on main 3c4abe2, statusline_hook.envelope returns None for tool_use plus tool_confirmation_pending=true and a valid session ID. The collector also has no wait route. No live Antigravity false clear was reproduced.

Classify as a bug in the repeating-source integration contract. The 2026-09-15 cycle-2 refresh reports Todo, High/M, journey:stopped-at-gate and move:keep, no comments and no blockers. DRC-4573 is Done and relatedTo DRC-4203; its captain-approved ruling selects the 300-second evidence lease and visible unconfirmed state. The initial baseline branch search found no drc-4203 branch. Relations fetched: DRC-4186 Done (positive capture, deliberately no mapping), DRC-4014 Done (explicitly closed with this gap), DRC-4379 In Progress (explicit resolve adapter, separate worker), DRC-4190 Canceled (wrong Pi approval premise), DRC-4183 and DRC-4192 Done (notifications already fixed). The project's live overview has no dated As of block and says the milestone owns remaining corrections; no overview edit is warranted.

Unknown unknowns: the source is a render, not a heartbeat clock; identical states are deduplicated by statusline_hook.decide. Overlay drops Event.source_instance_id and event name, and observation._remember stores one value per kind/session. A harness name alone cannot distinguish a statusline render from a lifecycle edge. N-3 forbids using an unrecognised hint to win precedence; N-7 requires answered question detail to disappear and forbids inventing a prompt reason from raw hook text.

## Proposed approach

Apply [DRC-4573](https://linear.app/recce/issue/DRC-4573): deliver the repeating-source reducer and visible uncertainty display. A recognised positive pending observation starts or renews a 300-second evidence lease while retaining the first blocked_since. Ordinary Working/Idle heartbeats neither clear nor renew it. At 300 seconds without a fresh positive observation, visibly mark the wait unconfirmed; never infer an answer or safety. Explicit matching resolution/session-end evidence permanently retires the wait.

Carry bounded, trusted source classification and semantic event cause through the reducer/coordinator before changing precedence: Overlay currently drops Event.source_instance_id and event name, and the ledger stores one value per kind/session. Preserve the other harness contracts, including Claude/Codex lifecycle and own-transcript retirement and OpenCode/Pi explicit-resolution waits without timeout. Keep AGY mapping, install, coverage admission and native validation separate.

Removing Working/Idle from ENDS_A_WAIT globally remains rejected because it breaks genuine resolution and resurrects old waits. Expiry straight to Working/Idle without visible uncertainty remains rejected because silence can accompany a real standing prompt. Five minutes is the approved product threshold, not a measured safe maximum. No further product ruling is needed; FO must bind the matching triage gate before implementation publishes these drafts.

```
## User value

A person waiting on an Antigravity session's confirmation notices this once the gate queue stops clearing their wait the moment the next ordinary status render arrives. P3, keep: without a precedence rule the queue would tell them nothing needs them while a confirmation is still standing, which is untrue.

## What needs to be done

Antigravity's status line repeats `tool_confirmation_pending: true` as a live render, not an edge. The overlay reducer in `events.py` maps the next ordinary `working`/`idle` render to an overlay that ends the wait, so the reader is told once and then told the opposite, up to 145s of silence between renders.

Add a precedence rule to the shared overlay reducer: a wait outranks a later `working`/`idle` push from the same source until it is answered or a deadline lapses. Add the deadline too, since a wait with no expiry recreates the sticking bug this reducer already guards against. Read `docs/design-needs-input.md`'s N-3 and N-7 before choosing the shape.

Acceptance criteria:

* A wait posted from a repeating source survives the next ordinary render, with a test that fails on today's reducer.
* It lapses on a deadline rather than sticking forever, with a test.
* The design record says which rule was chosen and what it costs.
```

## Historical decision proposal — superseded 2026-09-15 by DRC-4573

This section preserves cycle 1's undecided alternatives. It is history, not current instructions; DRC-4573 approved the five-minute source-specific lease, reducer and uncertainty display, with AGY admission separate.

Question: **May a recognised repeating-source confirmation become explicitly unconfirmed after a finite period without a new positive observation, while Cargento continues to disclose that the person may still be blocked?**

Recommend yes to that evidence distinction, with no inferred answer and no duration selected by this triage. It prevents a stale observation from remaining a current claim forever without hiding the possibility of a real standing prompt. If the captain requires a concrete initial duration, 300 seconds from the last recognised positive observation is an available product choice, not a measured safe bound or a reuse of the ask contract. It exceeds the longest captured silent interval (144.6 seconds) but that supplies no upper bound; a real confirmation may outlast it. Normal Working/Idle updates must neither resolve nor refresh that lease. Repeated positive observations may refresh evidence while preserving the first blocked_since.

| Option | What it buys | Cost and limit |
| --- | --- | --- |
| Source-specific evidence lease plus visible unconfirmed state (recommended direction) | Stops claiming stale evidence is current without claiming the wait was answered | Requires an approved duration and reader-state scope beyond the narrow reducer; see additional runtime/oracle estimates. Continued real gates can outlast every finite duration. |
| No finite expiry; explicit positive resolution/liveness evidence only | Preserves real silent waits and the current permission contract | Cannot satisfy the original finite-deadline AC. AGY answer/liveness semantics require further measurement before an adapter can use it safely. |
| Finite expiry to ordinary Working/Idle, with no uncertainty disclosure | Smallest code diff | Rejected: a real silent wait can vanish as though nobody needs the person, contradicting P3 and the measured absence behavior. |

Why an expiry might be needed: a render-driven positive observation has no guaranteed future answer edge, so a lost source can retain a current wait claim indefinitely. Why it is not already justified: the same silence occurs while a gate is genuinely open. The 90-second Working TTL answers whether a session still looks active; the 300-second ask deadline ends Cargento's own mailbox contract; neither settles the lifetime of someone else's permission prompt.

Independent build-boundary question: **Should DRC-4203 remain the reducer prerequisite, leaving AGY adapter admission, coverage, installation and live verification to a separately scoped build?** Recommend yes. It matches the original three acceptance bullets and prevents an unestimated adapter rollout. If the captain wants immediate user-visible AGY delivery, combine only after re-estimating mapping, source observation semantics and UI uncertainty; do not claim this triage has approved that.

Blocker scope to file by FO: one product decision linked as blocking DRC-4203's implementation, covering source-specific expiry semantics/duration and the AGY build boundary. It does not block DRC-4379 or DRC-4380 and must not impose expiry on their explicit-resolve wait pairs. No decision issue was filed or relation changed by this worker.
