[DRC-4556](https://linear.app/recce/issue/DRC-4556/a-detached-daemons-diagnostics-can-sit-unflushed-for-the-life-of-the) — A detached daemon's diagnostics can sit unflushed for the life of the process, so a store-write failure never reaches the log

## User value

A store fails to write, the server records why, and you see it immediately in the log while the process is running rather than only after it exits. P1, keep.

## Problem

When the daemon forks and redirects stdio in `lifecycle.daemon_redirect_stdio(log_file)`, fd 1 and fd 2 are replaced with the opened log file via `os.dup2`. However, in Python 3, `sys.stdout` and `sys.stderr` TextIOWrappers retain default block buffering (typically 4096 or 8192 bytes) when connected to a file. Diagnostics written via `runtime_io.diag` or `print()` sit unflushed in the buffer indefinitely until process exit.

## Proposed approach

1. In `cargento_runtime/lifecycle.py`:
   - In `daemon_redirect_stdio(log_file: str)`:
     Reconfigure `sys.stdout` and `sys.stderr` with `line_buffering=True`:
     ```python
     for stream in (sys.stdout, sys.stderr):
         with contextlib.suppress(AttributeError, io.UnsupportedOperation):
             stream.reconfigure(line_buffering=True)
     ```
2. In `tests/test_lifecycle.py`:
   - Add a test proving that after `daemon_redirect_stdio`, writing a diagnostic to stdout without an explicit flush immediately appears in the log file while the process is alive.

## Acceptance criteria

- AC1 (offline): A diagnostic written by a detached daemon is readable in its log file before the process exits. Verified by: subprocess test in `tests/test_lifecycle.py` that redirects stdio, prints a line, and verifies log content while the process is still running.

## Test plan

- Subprocess test in `tests/test_lifecycle.py` verifying immediate line flush after `daemon_redirect_stdio`.
- Run full test suite with coverage report.

## Review depth

Two lenses plus an arbiter (calibrated for daemon stdio).

## Out of scope

Modifying call sites of `runtime_io.diag` or changing foreground logging behavior.
