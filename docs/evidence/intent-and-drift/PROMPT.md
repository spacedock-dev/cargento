# Exploratory sidecar prompt for a teammate's agent

This prompt supports optional exploratory feedback and names the panel's controls. The owner removed the cold-study requirement on 2026-10-06; no cold participants need to be reserved. [The evidence guide](README.md) describes the current scope.

---

I use Claude Code for real development work. I authorize you to start Cargento locally for this study. I understand that Cargento scans available session stores across its supported harnesses, so its local board may show other sessions' titles and prompts. You may inspect metadata for my three most recent Claude Code sessions in this project and, after I choose one, read that session's transcript. Do not inspect or report the other sessions the board discovers. My coding agent may send the selected material it reads to its own model provider. Cargento's separate Analyze action may send a bounded reading to the provider named on its consent screen; I will make that choice in the browser. Do not press Allow for me or share session material elsewhere without asking.

Use the latest `origin/main` of `spacedock-dev/cargento`. Follow `AGENTS.md`, `cargento/skills/cargento/SKILL.md`, and `docs/evidence/intent-and-drift/README.md`. This is exploratory evidence, not a cold-study human verdict or a qualification case. Do not change Cargento code, the case corpus, the scoring ledger, or the Claude producer gate.

1. Prepare an isolated, detached checkout of `origin/main` and record its full SHA. Start its documented `server.py` launcher on an unused loopback port with a new private `CARGENTO_HOME`. This separate process and state directory are the sidecar. Do not stop or reuse my existing dashboard. Leave `--observer-model` off; reader-requested Analyze does not need it. Do not set `--no-observer-model` for a pass that may Analyze, because that disables model calls. Record flags without publishing private paths.
2. Shortlist the three freshest Claude Code sessions in this project by approximate time and a safe brief title. If a selected session is older than the default 24-hour board window, restart the sidecar with the documented `--window-hours` flag, wide enough to include it. The all-sessions view (`?all=1`) lists an older row but does not read its transcript, so its drift panel stays empty. Let me choose a real session with enough recorded work. Record why a newer one was skipped. Do not manufacture or edit a transcript. Inspect only my chosen session's contents.
3. Before spending an attempt, check the chosen row's disclosed reading route and whether its named provider is available. The Claude producer may still be gated; do not bypass it or claim a result from a disabled route. Ask me to approve the goal and expected-outcome lines against what I actually requested. Then operate the browser yourself as a reader would: save intent, enable the live monitor, and inspect the estimate. A reading needs a turn stop or session end that the sidecar itself observed, and a sidecar started after my session went quiet has observed neither, so Analyze is withheld as "idle with no stop and no end observed". After the intent is saved, write a hooks file for the sidecar and ask me to run one more turn of the chosen session through it. The file holds `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `Stop` and `SessionEnd` command hooks, each `CARGENTO_HOME=<sidecar home> python3 <sidecar checkout>/cargento/skills/cargento/event_hook.py claude <sidecar port>`, and I resume with `claude --resume <session id> --settings <hooks file>` from this project. That form, with no other setting flags, was verified on 2026-10-01: the sidecar received the turn and its end. The next step of my real work is the best turn; a short reply also works, and the page then lists it as a later direction for me to settle. Then ask me to end that resumed session with `/exit`, so the sidecar observes a session end: an observed turn stop does not hold, because Claude Code appends a non-conversation record a few minutes after the stop and the row turns back to working (run [sidecar-0764de](run-sidecar-0764de.md) Finding 3). Before pressing, confirm the sidecar's `/api/data` row for the session shows an `ended_at`. Keep the session ID and paths out of the report. Then press Analyze if I choose to allow it, inspect result and citations, open Steer back, compare Copy with the displayed correction without putting its text in the report, and inspect Update intent instead. Record the actual wording, level source, line verdicts, cited entry numbers, disabled reasons, and any mismatch with a recorded check. Label every step `agent-operated`.
4. Limit this pass to one Analyze attempt on the chosen session. Ask before another attempt or another session. I must personally inspect and press Allow on the first-press disclosure; if you start a fresh sidecar or change origin, I must do that again. If I decline or the route is unavailable, continue only with states the product can show and record the reason. An estimate is not a completed analysis.
5. Save original screenshots locally under `docs/screenshots/intent-and-drift-sidecar/` in the retained checkout, with a descriptive step and actual viewport width. Have a person read each image before any verdict. If the browser cannot save a capture, mark that step `not observed`; do not substitute a source-code read or an accessibility-tree snapshot. Keep the checkout and its ignored screenshots until I have reviewed them and decided where the approved evidence goes. Stop only the sidecar server you started.
6. Copy `docs/evidence/intent-and-drift/RUN_TEMPLATE.md` to a new file under that directory with a random run label. Fill in only observed, participant-approved facts; mark the run `exploratory agent-operated`. Do not commit my name, session ID, absolute paths, exact prompt, code, transcript, saved goal, checklist, correction text, raw model output, credentials, URL tokens, or unredacted screenshots. Give a reason beside every missing observation. Let me review the public file and any redacted image. Commit only what I approve on a branch and open a PR into `main`, not a direct push. If I approve sharing evidence with the team, include the approved report link; otherwise record that the private evidence was not submitted.
7. Report the SHA, start flags, chosen-session age, browser and width, observed drift outputs, reviewed screenshots, model consent, attempt count, and unverified steps. Tell me the private checkout and scratch-home locations without putting those paths in Git. Leave both available for follow-up until I approve cleanup.

If a visible result disagrees with a real check, record the wording and entry numbers privately, then file a reproducible issue in the Intent and drift milestone with my approval. Do not silently change the panel or call this a human usability pass.
