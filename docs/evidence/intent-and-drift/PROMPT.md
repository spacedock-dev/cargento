# Prompt for a teammate's agent

Send the text below to the agent working with a developer who did not build the Intent and drift panel. The developer should read the privacy and model-use paragraph before sending it. The study begins with the human walk; the agent-operated sidecar pass comes later.

---

I use Claude Code for real development work. I authorize you to inspect the metadata of my three most recent Claude Code sessions in this project and, after I choose one, to read that session locally for this Cargento study. My coding agent may send what it reads to its own model provider. Cargento's separate Analyze action may send a bounded reading of the selected session to the provider named on its consent screen; let me make that choice in the browser. Do not press Allow for me, start another model-based analysis, or share my session material outside this study without asking.

Use the latest `origin/main` of `spacedock-dev/cargento`, not an installed release or an old feature branch. Follow this repository's `AGENTS.md`, the shipped `cargento/skills/cargento/SKILL.md`, and `docs/evidence/intent-and-drift/README.md`. Treat this as evidence collection for DRC-4722 and the remaining Intent and drift verification issues. Do not change Cargento code, the qualification case corpus, the scoring ledger, or the Claude producer gate.

1. Prepare an isolated, detached checkout of `origin/main` and record its full commit SHA. Start Cargento from that checkout using its documented `server.py` launcher, on an unused loopback port and with a new private `CARGENTO_HOME`. This is the sidecar: a separate dashboard over my real local sessions, with its own saved intent and consent state. Do not stop or reuse a Cargento instance I already run. Leave `--observer-model` off; a reader-requested Analyze is available without it. Do not use `--no-observer-model` for the human walk, because that disables Analyze. Tell me the local URL and the exact start flags. Stop only the process you started when the study ends.
2. Show me a short list of the three freshest Claude Code sessions in this project: approximate time, project, and a brief title if it is safe to display. Do not print transcript contents or session IDs in the report. Let me choose one that represents real work and has enough recorded turns to inspect. Record why any newer session was skipped. Do not make a synthetic session or edit a transcript to get a favorable result.
3. Open Chrome to the Sessions view and find the chosen row. Give me exactly this task, then stop coaching: "Find out whether this session is still doing what you asked, and if it is not, get it back on track." I must drive the browser by hand from that row. Observe without clicking, suggesting labels, or explaining the panel. Record elapsed time and presses to the first result and to a copied correction; note each hesitation and the screen where it happened. If the page asks for consent, I decide in the browser. If I decline, record the refusal and do not work around it.
4. During my uncoached walk, record whether I notice and check the drafted goal, whether I supply expected-outcome lines, the live estimate, any later-direction choice, the analysis phases, the result level and its source, each outcome verdict, cited entry numbers, "Can't tell," Steer back, Update intent instead, and whether I paste a correction. Do not prompt me to use a control or repair my intent while the walk is underway. Record exactly what appeared and what could not be reached. Do not invent a result or treat a live estimate as a completed analysis. One completed Analyze attempt is enough for the first walk; ask me before any additional attempt because it spends my model capacity.
5. After the walk, ask me these three questions without supplying an answer: "What did the level tell you?", "Would you leave the live monitor on?", and "What would you have done without Cargento?" Record my answers in my words in a private note. Ask me which words, if any, I approve for the public report. Keep the full answers for the DRC-4722 issue attachment only if I approve that destination too.
6. Only after my uncoached walk, ask me to check the drafted goal and the expected-outcome lines against what I actually asked. Then you may perform one separate `agent-operated` pass on a fresh scratch Cargento home, using only the goal and lines I approved. Imitate the browser steps a reader would take: confirm intent, switch on the live monitor, inspect the estimate, Analyze if I explicitly allow another call, inspect the result and citations, open and copy Steer back, and inspect the next-step choice. Capture the rendered strings, level source, per-line verdicts, citation entry numbers, disabled reasons, and any mismatch with the recorded checks. This pass is technical evidence, not a second human usability participant. If Analyze is unavailable, record the exact reason and continue with the states the product can show. With my separate approval, repeat this technical pass on another session from the three-session shortlist; give each session its own run file and model-call count.
7. Save original screenshots locally under `docs/screenshots/DRC-4722/` with descriptive step and width names. Record the actual viewport width. A person must read every screenshot before assigning a pass or fail verdict. If you cannot capture or inspect a state, mark it `not observed`. Never claim that a source-code read, unit test, or accessibility-tree snapshot is a screenshot verdict. Keep raw process and network traces local if you collect them.
8. Make a copy of `docs/evidence/intent-and-drift/RUN_TEMPLATE.md` under that directory with a random run label. Fill it with observed facts and a `human-operated` or `agent-operated` label for each run. Do not put my name, session ID, absolute paths, exact prompt, code, transcript, saved goal, checklist, correction text, raw model output, credential, URL token, or unredacted screenshot into Git. Use short, participant-approved descriptions of the work and keep exact UI strings only when they contain no private text. Put a missing-data reason beside every blank field. Have me review the proposed public file and any redacted image. Commit only what I approve on a branch and open a PR into `main`; do not push directly to `main`. If I approve a Linear attachment, add the issue-comment link to the public report. Otherwise leave the attachment field blank and mark the DRC-4722 verdict incomplete.
9. Report the checkout SHA, start flags, chosen-session age, both run modes, presses and elapsed times, observed drift outputs, screenshot review status, whether model consent was granted, attempt count, and what remains unverified. Stop your sidecar server and remove only your own temporary checkout. Tell me where its private scratch home remains so I can decide when to delete it after the evidence has been reviewed. Never delete my existing Cargento state or Claude Code sessions.

If you find a defect, record the visible wording and a reproduction on the same SHA. Do not silently change the panel or mark DRC-4722 complete. A result from a participant who had built the panel, received hints, or watched the agent-operated pass first does not qualify as one of the issue's two cold walks.
