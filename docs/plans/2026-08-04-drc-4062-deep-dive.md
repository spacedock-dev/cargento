# Deep dive: DRC-4062, Usage section visual design

## Issue summary

Implement the "Usage" section from the Claude Design project (Cargento Ledger comp), including
the configure popover, and add the three things the ticket layers on top of the design: the
first-run disclosure modal with copy quoting the merged security contract, the expired-token
state, and an "as of" timestamp on every figure.

## Classification

**Type:** feature (frontend, design-to-code translation)
**Priority:** High
**Branch:** `feature/drc-4062-usage-visual-design-implement-the-claude-design-usage` (not created yet)

## Current state

- The design lives in the "Agent Dashboard redesign direction" project on claude.ai/design,
  readable through DesignSync. `Cargento Ledger.dc.html` is a React-rendered comp (`support.js`
  is its generated runtime, a visual reference only; production is vanilla JS).
- The comp's usage band sits inside the calm-mode ledger frame: a `usage` chip in the controls
  bar (keyboard `u`, persisted at `cargento.usageOpen`), a four-column per-harness grid (icon and
  name, then a row per window: label, bar, percent, reset time), tone thresholds at 70 (warn) and
  90 (attention), an extras line (burn, today, cost), and a "configure" popover with per-stat
  checkboxes persisted at `cargento.usageCfg`, at least one stat always locked on.
- The design has no disclosure modal, no expired-token state, and no per-harness "as of"
  timestamp. Those are the ticket's additions, not omissions to copy.
- Production `app.js` already carries the calm-mode ledger from this same design direction: the
  same `cargento.displayMode` localStorage key, tone and rail tables, a delegated `data-calm`
  click handler, and a document-level keydown listener. The band integrates into an existing
  surface rather than a new page.
- `/api/data` carries no usage data yet. DRC-4063 (Codex tile) and DRC-4064 (Claude fetcher)
  supply it later, so this ticket defines the payload shape and renders an empty state until
  then.
- The frontend is three source files (`web/app.js`, `web/styles.css`, `web/index.html`) assembled
  by a byte-preserving loader; `scripts/lint_embedded.py` checks JS syntax, CSS structure, and
  DOM id references.

## Acceptance criteria

1. Calm mode has a `usage` chip in the controls bar; clicking it or pressing `u` toggles the
   band; the choice persists across reloads.
2. The band renders per-harness windows with bars, percentages, and reset times, matching the
   comp's layout, typography, and tone thresholds, in light and dark themes.
3. The configure popover toggles the five stats, persists, and refuses to uncheck the last one.
4. Every rendered figure carries an "as of" timestamp.
5. An entry whose token is expired renders switched off with an exclamation and a note or button
   pointing at refreshing the login in the harness; no numbers show for it.
6. The first-run disclosure modal exists with copy quoting the contract, carries the off switch,
   and ships dormant: it triggers on a server-sent capability field that only DRC-4064 will send.
7. With no usage data in the payload, the band shows a quiet empty state and nothing errors.
8. `lint_embedded.py` and the full pre-PR gate pass.

## Risks and open questions

- Scope was widened at kickoff to both display modes, and the design already covers it: the
  regular-mode comp (`Agent Dashboard.dc.html`) carries its own "Usage · rate limits" section
  between the pulse tiles and the needs band, sharing the same configure state. One band renderer
  serves both placements.
- The modal gates a fetch that does not exist yet. It ships dormant behind a capability field,
  so users see nothing new until DRC-4064; the copy still lands now and is review-able.
- The payload shape for usage entries is defined by this ticket and consumed by DRC-4063/4064:
  per harness, window percents and reset times, optional extras, an `asOf` timestamp, and a
  state field distinguishing ok from expired.
- The design's extras (burn, today, cost) have no data source in the current chain (burn is A5,
  unshipped). They render only when present; the configure rows stay so the design is complete.

## Proposed approach

Translate the comp into the existing vanilla-JS idiom on the issue branch: chip and keybinding
into the calm controls and keydown handler, band and popover as new render functions reading
`data.usage`, modal as a dormant overlay, styles following the comp's inline-style-with-classes
pattern. Verify with the pre-PR gate plus a live run of the dashboard against a machine with no
usage data (empty state) and a mocked payload (full band, expired entry, modal).
