# Deep dive: DRC-4061, SECURITY.md scope section for the quota fetcher

## Issue summary

Write the security contract for the quota fetch decided in DEC-1 (DRC-4053) before any fetcher
code exists: a third network-behaviour section scoped the way the Spacedock project-reads section
is scoped, so the implementation PR is held to a published standard instead of writing its own.

## Classification

**Type:** documentation (a spec deliverable, not a code change)
**Priority:** High
**Labels:** none
**Branch:** `feature/drc-4061-quota-groundwork-securitymd-scope-section-for-the-quota` (does not exist yet)

## Current state

- `SECURITY.md` opens with "Cargento ships two components that touch the network" and rests on two
  invariants: loopback-only listening, read-only harness stores. The Spacedock project-reads
  section is the scoping model to copy: exactly what is read, the validation ladder, hard caps,
  what reaches the API, and the off switch.
- `SKILL.md` line 153 documents `--diagnose` as "Reads local paths only; nothing is transmitted."
  DEC-1 concluded that sentence stays true as long as the diagnostic pass never triggers a fetch.
- `scripts/validate_plugins.py` resolves every relative link and heading anchor across the owned
  docs (SECURITY.md is in the set) and rejects the `localhost` spelling of the dashboard URL.
- The sync-docs voice standard greps SECURITY.md and `docs/plans/*.md`: no em or en dashes, no
  curly quotes, sentence-case headings, no mechanical boldface.
- Precedent for the off switch: `--no-spacedock` disables the one feature that reads outside the
  store roots. The quota flag should follow that naming shape.

## Acceptance criteria

1. A quota-fetcher scope section exists, modelled on the Spacedock project-reads section: exactly
   what is read, exactly what is sent, hard boundaries.
2. The contract sentences appear: the request carries the harness credential and nothing else; the
   response is quota numbers; no session data in either direction, ever; the token is never
   refreshed; an expired token switches that harness's usage display off with a pointer to refresh
   the login in the harness itself.
3. Endpoints are named per vendor (Anthropic first; Codex needs none, its numbers are read from
   disk), with the plain statement that a vendor can break or block them at any time.
4. The consent surface is documented: the opt-out flag and the first-run modal, on by default, off
   switch in the modal, re-enable later from configure.
5. The polling posture is documented: responses cached, a minimum interval held between calls.
6. The two existing invariants read unchanged, and the `--diagnose` sentence in SKILL.md stays
   true.
7. `validate_plugins.py` passes, and the prose meets the voice standard.

## Risks and open questions

- **Where the section lands is the real question.** SECURITY.md describes the shipped product. If
  this ticket amends it directly, then between this merge and the fetcher merge, main's security
  policy describes a network behaviour the code does not have. Two honest ways out: draft the
  section as a plan doc that the fetcher PR promotes into SECURITY.md verbatim (keeps the policy
  truthful at every commit, and satisfies DRC-4053 guardrail 3, which wants the SECURITY.md change
  in the same PR as the code), or amend SECURITY.md now with one sentence marking the section as
  taking effect with the release that ships the feature. The ticket's done-when says "merged into
  SECURITY.md", so this needs the owner's call.
- The exact Anthropic usage endpoint is not yet pinned. Barista and the cortexkit/anthropic-auth
  extension both call Anthropic's authenticated OAuth usage endpoint; the draft must name the URL
  after confirming it from one of those sources, not from memory.
- The opt-out flag is unnamed. Proposal: follow `--no-spacedock` and call it `--no-usage`, with the
  modal's switch writing the same setting.
- The modal itself is DRC-4062's deliverable. This section documents what the modal promises, so
  DRC-4062 copy must quote it, not paraphrase.

## Proposed approach

See the proposal presented in session. Short form: branch, draft the section (home per the owner's
call above), name the endpoint from source, run the validator and the voice pass, PR via the
pre-PR gate, and leave DRC-4062 unblocked only when merged.
