[DRC-4548](https://linear.app/recce/issue/DRC-4548) — "Harness does not report turn bounds" renders on every idle and needs-input Claude row, though Claude reports them

## User value

You open a Claude session that is waiting on you and its `TURN` row says the harness does not report turn bounds. Proposed P2, sharpen: **an absence says what is absent, not something false about the harness.**

## Problem

`turns.turn_progress` returns `None` unless `session_state == "working"`, and `web/next-observed.js:149` turns that absence into "Harness does not report turn bounds". Seen on the session page `TURN` row of idle and `needs_input` Claude rows during the 2026-09-12 Mode 1 walk on main at `08c07ad`. Claude does report turn bounds; the honest sentence for a non-working row is that no turn is in progress.

## Proposed approach

1. In `cargento/skills/cargento/cargento_runtime/aggregate.py`:
   - Add `reports_turn_bounds: bool = True` to `HarnessSpec` (defaulting to `True`, set to `False` on `cursor`).
   - Include `"reports_turn_bounds": spec.reports_turn_bounds` in `_harness_summary`.
2. In `cargento/skills/cargento/cargento_runtime/web/next-observed.js`:
   - Determine whether the harness reports turn bounds (`turnReporter`):
     `harness && !harness.error ? (harness.reports_turn_bounds !== false && harness.key !== "cursor") : false`.
   - Distinguish non-working absence from a harness that publishes no turn bounds:
     If `turnReporter` is true, render `"No turn in progress"` when non-working (or `"Turn bounds not published"` if working without bounds).
     If `turnReporter` is false, render `"Harness does not report turn bounds"`.
3. In tests:
   - Update asset byte and digest pins across `test_next_page.py`, `test_next_flag.py`, `test_focus.py`.
   - Add unit tests in `test_next_session.py` / `test_next_observed.py` verifying:
     - An idle Claude row renders "No turn in progress".
     - A needs-input Claude row renders "No turn in progress".
     - A harness that publishes no turn bounds (e.g. Cursor) renders "Harness does not report turn bounds".
4. Run full pre-PR verification suite.

## Expected surface and tolerance

Estimate: ~25 net LOC across 5 files (`aggregate.py`, `next-observed.js`, `test_next_session.py`, `test_next_page.py`, `test_next_flag.py`, `test_focus.py`), tolerance ±30%.
Semantics this may change: UI display on non-working session cards and inspection rows.

## Acceptance criteria

Verified by: `observed.turnText == "No turn in progress"` and `observed.turnKnown == false` for an idle Claude session row.

**AC-2 — Needs-input Claude row renders "No turn in progress"** (offline)
Verified by: `observed.turnText == "No turn in progress"` and `observed.turnKnown == false` for a needs_input Claude session row.

**AC-3 — Harness with no turn bounds renders "Harness does not report turn bounds"** (offline)
Verified by: `observed.turnText == "Harness does not report turn bounds"` and `observed.turnKnown == false` for a Cursor session row.
