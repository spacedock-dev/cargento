[DRC-4551](https://linear.app/recce/issue/DRC-4551/sigterm-leaves-the-ports-state-file-behind-though-lifecycle-documents) — SIGTERM leaves the port's state file behind, though lifecycle documents its removal before the port closes

## User value

You stop the board with a signal (e.g. systemd, container stop, kill) and the next `--status` sees no stale state file, honoring the documented lifecycle invariant that the process cleans up its own state file on shutdown. P1, keep.

## Problem

`lifecycle.serve()` has a `finally:` block that calls `remove_state(config, port)` and `server.server_close()`. However, under Python's default signal disposition, `SIGTERM` terminates the process immediately (`SIG_DFL`) without unwinding the stack, bypassing the `finally:` block and leaving `cargento-<port>.json` on disk.

## Proposed approach

1. In `cargento_runtime/lifecycle.py`:
   - In `serve()`:
     Register a `signal.SIGTERM` handler that calls `sys.exit(0)` (raising `SystemExit`).
     This causes `serve_forever()` to exit, running the `finally:` block which removes the state file, releases streams and closes the server.
     Restore the previous signal handler in `finally:`.
     Safely handle environments where `signal.SIGTERM` is unavailable or non-main threads raise `ValueError`.
2. In `tests/test_lifecycle.py`:
   - Add a test that starts a server subprocess, sends `SIGTERM`, verifies the process exits with code 0 and verifies that its state file has been removed.

## Acceptance criteria

- AC1 (offline): After a `SIGTERM` to a serving process, the state file is gone. Verified by: subprocess test in `tests/test_lifecycle.py`.

## Test plan

- Integration/subprocess test in `tests/test_lifecycle.py` verifying state file deletion upon receiving `SIGTERM`.
- Run full test suite with coverage report.

## Review depth

Two lenses plus an arbiter (calibrated for signal handling and cleanup).

## Out of scope

Changing HTTP `/api/shutdown` behavior or changing `--stop` semantics.
