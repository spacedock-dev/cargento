[DRC-4034](https://linear.app/recce/issue/DRC-4034) — H2 · Reach the user away from the desk

## User value

A person who steps away from their desk notices this when a session needing their input sends a nudge to their mobile device or webhook endpoint, instead of sitting unnoticed in an unobserved browser tab. P2, move:extend: extends Cargento's notification promise beyond local desktop windows to off-machine destinations.

## Problem

Today all notifications require the operator to be in front of the machine (macOS popup, or an open browser tab on Linux/Windows). DEC-4 ruled on 2026-09-02 that Cargento may post counts to an operator-supplied endpoint off this machine. SECURITY.md defines the strict contract:
1. Off until a URL exists (no default endpoint).
2. Exactly one destination (the operator's URL), following no redirects and ignoring proxy environment variables.
3. Counts and states only: the payload carries how many sessions need a human (`needs_input`) and how many finished unread (`finished_unread`), and never any session id, project name, path, prompt, or request text.
4. Throttled: at most one POST per configured cooldown interval, triggered by a change in counts.
5. Credential protection: the webhook URL is a bearer token and must never be logged, echoed in API responses, or printed by `--diagnose`.
6. Off switch: `--no-reach` disables the pathway regardless of any stored or configured URL.

## Proposed approach

1. **Configuration & CLI surface**:
   - Add `--no-reach` flag to `cli.py` to disable reach for a run.
   - Support supplying the reach endpoint via:
     - CLI flag `--reach-url <URL>`,
     - Environment variable `CARGENTO_REACH_URL`,
     - Or file `reach_url` inside `state_dir` (`~/.cargento/reach_url`).
   - Add `reach_enabled: bool` and `reach_url: str | None` to `RuntimeConfig` in `config.py`.
   - Add `reach_interval_sec: float = 60.0` to `RuntimeConfig`.

2. **Reach delivery module (`cargento_runtime/reach.py`)**:
   - Encapsulate off-machine delivery in a dedicated module.
   - `build_reach_opener()`: creates opener with `urllib.request.ProxyHandler({})` and custom `_NoRedirects` HTTPRedirectHandler.
   - `send_reach_nudge()`: formats strictly `{"needs_input": int, "finished_unread": int}`, executes HTTP POST with timeout, and catches/swallows network exceptions without crashing.
   - Redaction: ensure URL is never printed in logs or diagnostics.

3. **Application integration (`cargento_runtime/aggregate.py`)**:
   - In `Application.collect()`, calculate current counts:
     - `needs_input`: count of active sessions with `state == "needs_input"`.
     - `finished_unread`: count of inactive/ended sessions not yet dismissed or handled.
   - When counts change and cooldown interval has elapsed since the last nudge, trigger reach nudge asynchronously or outside the hook lock.

4. **Security & Documentation contracts**:
   - Update `SECURITY.md` to document the shipped reach feature and `--no-reach` switch.
   - Update `cargento/skills/cargento/tests/test_documentation.py` to assert the updated contract and parser behavior.
   - Document usage in `HOW_TO_USE.md`.

## Acceptance criteria

1. **User-visible:** When a reach URL is configured and an active session enters `needs_input`, an HTTP POST is dispatched to the endpoint containing only `{"needs_input": <count>, "finished_unread": <count>}` and no identifying session data. Verified by: offline test against a local HTTP server.
2. **Security & Boundary:** With no URL configured, or when `--no-reach` is passed, no outbound HTTP request is attempted. Verified by: offline unit test asserting 0 requests dispatched.
3. **Security & Boundary:** The reach request ignores proxy environment variables (`http_proxy`, `https_proxy`) and refuses HTTP redirects (301, 302, 307, 308). Verified by: unit test exercising proxy and redirect refusal.
4. **Security & Boundary:** The webhook URL is never exposed in `--diagnose` output, server logs, or `/api/data` responses. Verified by: test asserting absence of URL across all diagnostic outputs.
5. **Regression:** Full test discovery, linting, formatting, type checking, and documentation verification pass. Verified by: pre-PR checks.
