[DRC-4032](https://linear.app/recce/issue/DRC-4032) : Linear priority Low, estimate XS.

## Problem

A person protecting a block of deep work or sleep needs Cargento to suppress notifications during configured hours instead of pinging them for every state change. Currently, notification popups (`maybe_popup`, `handle_payload`, `unasked._raise`, `tripwires.collect`) and off-machine reach nudges (`reach.maybe_reach_nudge`) fire whenever transitions occur, without respecting user-configured quiet hours.

## Proposed approach

1. Add settings surface for quiet hours:
   - CLI flag: `--quiet-hours HH:MM-HH:MM` (e.g. `22:00-08:00` or `13:00-15:00`)
   - Rollback/disable CLI flag: `--no-quiet-hours`
   - Env var: `CARGENTO_QUIET_HOURS`
   - Stored setting file: `~/.cargento/quiet_hours` (read if no CLI flag or env var is set)
2. Add parsing and validation helper `parse_quiet_hours` in `notifications.py`.
3. Add `is_quiet_hours(config, *, now=None)` in `notifications.py` checking local time against the window (supporting windows spanning midnight like `22:00-08:00`).
4. In `notifications.py`:
   - `maybe_popup`: if `is_quiet_hours(config, now=now)`, suppress popup and return early.
   - `handle_payload`: if `is_quiet_hours(config, now=now)`, do not fire popup.
   - `maybe_ask_popup`: DO NOT suppress. Direct questions must still fire.
5. In `unasked.py` (`_raise`), `tripwires.py` (`_collect`), and `reach.py` (`maybe_reach_nudge`): suppress raises/nudges during quiet hours.
6. In `lifecycle.py` (`spawn_argv`): forward `--quiet-hours` and `--no-quiet-hours` to daemon child.
7. Unit tests in `test_notifications.py`, `test_cli.py`, `test_lifecycle.py`, and `test_reach.py`.
