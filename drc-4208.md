### Deep dive through proposal

- Contract read first: `docs/design-adapter-packaging.md` A-2 requires measured per-harness identity before admission; A-4 requires byte-identical hook copies. A-1 concerns in-process JavaScript adapters and does not forbid the existing Python hook route for Droid's subprocess hooks.
- `docs/captures/droid/notification-0.202.0-macos.jsonl` records two noninteractive exec sessions on Droid 0.202.0, before its authentication gate. A project-local replica of the Claude plugin layout actually loaded and ran SessionStart/SessionEnd with literal argv `claude`. This was a recorder with no network call, not an observed POST to a dashboard.
- Its separate synthetic route experiment proves the consequence; a bounded fresh replay on this baseline agrees: `event_hook.envelope(..., "claude")` emits session_started, the parser admits it as Claude with sid `12345678`, while Droid's envelope is absent and parser returns `unknown-harness`. Actual fresh network leakage was not claimed or induced.
- Command interpolation is NOT exported environment identity. The recorded commands reached the expanded plugin root, but both root environment variables held unexpanded sentinels. Both Claude and Droid project variables were present. Checking merely whether a Droid root variable exists is therefore not established as a safe discriminator.
- Four per-event identity verdicts across two sessions measured hook session_id, session_start.id AND transcript filename stem as equal, 36 characters and UUID-shaped. Three transcripts agreed on header versus filename. This supports a bounded full-ID normalizer for the measured version, not an assertion that every Droid version uses UUIDs.
- Fresh isolated collector replay returns the same full ID with a normal header, absent session_start header, and a renamed file whose header retains the ID. A malformed-header fixture is still owed in implementation. No alias from the Claude eight-character prefix is permissible.
- Notification was never captured on Droid. Permission/idle/elicitation vocabulary came from a binary read, and interactive launches did not pass login. The issue must not silently become a Droid gate adapter or change `reports_needs_input=False`.
- Installed CLI version was read directly: `droid --version` returns 0.210.0. The committed 0.202.0 capture therefore does not certify the currently installed plugin loader; no new Droid session was launched during triage. AC-3 must pin and measure its actual version.
- `validate_hook_vocabulary` maps one harness to one file and checks literal argv. A green on the shared Claude file does not establish what another harness loads. New-root packaging must include its own file inventory, vocabulary, literal-route check and duplicate-script parity.
- Unknown unknowns for the proposal: an explicit separate root cannot prevent a user deliberately installing the existing Claude root into Droid; default route fallback remains Claude; collector IDs are broader than a measured event normalizer; stale transcript presence is not proof a process is running.

## Proposed approach

This follows the Gemini packaging precedent and avoids an unmeasured environment discriminator. ### Original issue body — fetched 2026-09-15

````markdown
## User value

A person running Droid in a project that also has Cargento's Claude plugin installed notices this once Droid's own sessions stop vanishing from the board instead of posting to the wrong route. P1, keep: without a fix a Droid session's events reach a harness route that matches no row, so the board silently fails to show a harness it should be counting.

## What needs to be done

Droid loads Cargento's Claude plugin, whose only manifest directory is `.claude-plugin`, unwraps the hooks, and runs every hook command with the literal argument `claude`. Droid session events post to `/api/events/claude`, match no row, and vanish silently; `/api/events/droid` would be refused anyway, since `IDENTITY_NORMALIZERS` has no `droid` entry.

Pick one fix shape and record the choice: a separate `cargento-droid/` root, the answer `cargento-gemini/` already gives the same collision, or derive the harness from the environment, using the plugin-root variable Droid also expands, with `argv` as the fallback. Either way, add a `droid` entry to `IDENTITY_NORMALIZERS`. `collectors/droid.py` falls back to the filename when line 1 is missing or is not `session_start`, so an adapter that only checks `session_id == session_start.id` passes and still misses rows.

Acceptance criteria:

* A Droid session cannot cause Cargento's Claude hooks to run, by whichever route is chosen.
* `validate_hook_vocabulary` states in its own docstring that it cannot cover a file two harnesses read, so nobody reads its green as coverage.
* The design record says which shape was taken and why the other was not.
````
