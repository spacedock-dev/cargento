[DRC-4553](https://linear.app/recce/issue/DRC-4553/diagnose-writes-a-delivery-store-file-though-skillmd-says-it-writes) - --diagnose writes a delivery-store file, though SKILL.md says it writes nothing

## User value

Running server.py --diagnose leaves the file system untouched, honoring the contract in SKILL.md that --diagnose reads local paths only and writes nothing. P1, keep.

## Problem

SKILL.md:433 documents --diagnose as: "Reads local paths only; it writes nothing."
However, diagnose(application) calls application.collect(show_all=True). When any active session is in a needs_input state, application.collect calls self._notify_waits, which invokes notifications.maybe_popup. This triggers record_outcome, which calls deliveries.record(config, ...) and creates cargento-deliveries.json. In addition, tripwires.collect can trip conditions and record deliveries. Consequently, running --diagnose against a fresh environment creates files on disk.

## Proposed approach

1. In cargento_runtime/aggregate.py:
   - Add notify: bool = True parameter to Application.collect.
   - Guard self._notify_waits with if notify:.
   - Pass notify=notify to tripwires.collect so it evaluates rules without mutating disk or notifying when notify is False.
2. In cargento_runtime/diagnostics.py:
   - diagnose(application) invokes application.collect(show_all=True, notify=False).
3. Add a test in tests/test_config_diagnostics.py asserting that running --diagnose over a discovered session in needs_input state does not create cargento-deliveries.json or write to cargento_home.

## Acceptance criteria

- AC1 (offline): server.py --diagnose running against an environment with a discovered needs_input session leaves cargento_home empty. Verified by: subprocess test in tests/test_config_diagnostics.py.
- AC2 (offline): diagnose(application) with a needs_input session does not call deliveries.record or create files. Verified by: unit test in tests/test_config_diagnostics.py.
