[DRC-4347](https://linear.app/recce/issue/DRC-4347) — A teammate that dispatches its own teammate into a pane is reachable by nothing on the board

## User value

A person whose first officer dispatches an ensign that itself dispatches a named teammate into a pane sees that second-level teammate published on the board with its parent attribution and active status, rather than it being lost or discarded. P2, move:sharpen: fixes subagent reachability and resolves the unmeasured nested teammate dispatch boundary.

## Problem

Found during the teammate-visibility fix (DRC-4344) by reading the code path. In `collectors/claude.py`, top-level transcripts classified as children are bucketed into `agent_children[parent_prefix]`. When a child transcript's `parent_prefix` points to another child rather than a root session, that bucket lands under the child's prefix. Because the session loop iterates only the union of top-level `transcripts` and `tasks_by_session` (neither of which contains intermediate children), the bucket is silently discarded.

Measurement of the Claude Code harness reveals that all teammates in an agent team coordinate under the single shared team name `teamName: session-<leadSessionId[:8]>`, so the harness never naturally writes `session-<child-prefix>`. However, if nested child prefixes ever occur (whether via nested team dispatches, child attribution, or synthetic/future harness records), the collector must resolve child prefixes to the root session so they are published with appropriate parent attribution rather than dropped.

## Proposed approach

1. In `cargento/skills/cargento/cargento_runtime/collectors/claude.py`:
   - Document harness team coordinator behaviour: Claude Code assigns the shared team coordinator name `teamName: session-<lead-prefix>` to all spawned teammates, meaning teammate transcripts naturally bucket under the lead session.
   - When bucketing `agent_children`: maintain a mapping of child transcript prefixes to their declared parent prefixes.
   - For any child bucket whose parent is itself a child, resolve the root session prefix and attach the nested child to the root session's children, setting `parent` attribution to the intermediate parent's label.
   - Flatten the nested teammate's own workers (`child_agent_files`) directly beneath it with parent set to the nested teammate's label.
2. In `docs/captures/claude`:
   - Add capture evidence demonstrating that teammate transcripts and team registry coordination use the shared lead session team name `session-<lead-prefix>`, and record this in `docs/captures/README.md`.
3. In tests:
   - In `cargento/skills/cargento/tests/test_claude.py`:
     - Add `test_nested_teammate_with_child_parent_prefix_is_published_under_lead`: create root session A, child teammate B (parent A), and nested teammate C (parent B) with its own workers; verify C is published under A with parent="B", and C's workers are flattened under C with parent="C".
     - Add test verifying that teammates sharing `teamName: session-<lead-prefix>` both publish under the lead.
4. Update Linear issue DRC-4347 status to "In Progress".

## Expected surface and tolerance

Estimate: ~40 net LOC across 4 files (`collectors/claude.py`, `test_claude.py`, `docs/captures/README.md`, capture file), tolerance ±25%.

## Acceptance criteria

**AC-1 — Nested teammate with child parent prefix published under root session** (offline)
Verified by: A session where child C points to child B as parent_prefix, and child B points to session A, publishes both B and C under session A's subagent roster.

**AC-2 — Parent attribution links nested teammate to intermediate parent** (offline)
Verified by: Nested teammate C publishes with `parent` set to B's label, while B publishes with `parent: null` (or lead).

**AC-3 — Grandchild workers beneath nested teammate are flattened** (offline)
Verified by: Workers spawned by nested teammate C are published beneath C with `parent` set to C's label.

**AC-4 — Harness team coordinator behaviour documented in code comment and capture** (offline)
Verified by: Code comment in `collectors/claude.py` explains why harness team records share `session-<lead-prefix>`, backed by recorded capture in `docs/captures/claude`.
