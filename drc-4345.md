[DRC-4345](https://linear.app/recce/issue/DRC-4345) - Linear priority Medium, estimate XS, labels `discovered-by-agent`, `journey:mid-flight`, `move:keep`. Filed 2026-09-03 from H1's (DRC-4044) full-adversarial review: a write-primitive hardening shared by three writers, its own cycle by the captain's standing directive because it spans `lifecycle`, `dismissals` and `history`.

## User value

Hardens the owner-only file writing primitive shared across state, dismissals, and history stores so that the owner-only guarantee does not rest solely on the directory mode, and tightens directory permissions when ~/.cargento already exists.

## Problem

The state file writer (lifecycle.py), the dismissals writer (dismissals.py), and the history writer (history.py) all use the same pattern: create ~/.cargento with makedirs(exist_ok=True), open a predictable temporary file named `<target>.<pid>.tmp` beside the target without O_NOFOLLOW or O_EXCL, write, and rename over the target.
This has two weaknesses:
1. The temporary filename is predictable and opened without O_NOFOLLOW or O_EXCL, which could follow a pre-placed symlink if the directory permissions were relaxed.
2. makedirs(exist_ok=True) does not tighten the mode of an existing directory if it was created with looser permissions than 0o700.

## Proposed approach

1. Add a shared atomic write helper in `cargento_runtime/io.py`:
   - `ensure_owner_dir(path: str, mode: int = 0o700) -> None`: ensures directory exists and tightens permissions to `mode` on POSIX if looser.
   - `atomic_write_owner_only(target: str, content: bytes | str, *, encoding: str = "utf-8") -> None`: creates/tightens parent directory, generates a randomized temporary name `<target>.<pid>.<token>.tmp`, opens with `O_WRONLY | O_CREAT | O_EXCL` and `O_NOFOLLOW` (where supported) with mode 0o600, writes content, renames over target, and unlinks the temporary file on error.
2. Update `ensure_cargento_home` and `write_state` in `cargento_runtime/lifecycle.py` to use the shared helper.
3. Update `save` in `cargento_runtime/dismissals.py` to use `atomic_write_owner_only`.
4. Update `save` in `cargento_runtime/history.py` to use `atomic_write_owner_only`.
5. Add unit tests for `ensure_owner_dir` tightening permissions and `atomic_write_owner_only` atomicity and cleanup.

## Acceptance criteria

- `ensure_owner_dir` tightens pre-existing loose permissions (e.g. 0o755 to 0o700) on POSIX.
- `atomic_write_owner_only` uses randomized temporary filename beside target.
- Temporary file is opened with O_CREAT | O_EXCL and O_NOFOLLOW (where platform supports it) with mode 0o600.
- Existing tests and atomicity oracles in test_history and test_dismissals continue to pass.
- Temporary file is cleaned up if write or replace fails.
